03 — How I work

Falsification-first.
PoC before submission.

  1. Falsification-first

    Kill weak hypotheses before investing in a PoC. Most “bugs” die here. The ones that survive get a test.

  2. Test-before-submit

    Reproduce first. Report second. PoCs use the protocol’s native test stack — Foundry, Anchor, Rust, or TypeScript.

  3. Devil’s filter

    Who benefits. What is the concrete trigger. What is the honest-user harm. If that triangle doesn’t close, it isn’t a finding.

  4. Cross-check

    AI is a suggestion layer. Spec and code are the source of truth. I verify both before I write the report.

  5. Fuzz and invariants

    Fuzz and invariant suites to hit the paths unit tests miss, and to prove the protocol still holds under arbitrary input.
